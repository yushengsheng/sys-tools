# sys tools · Windows 系统工具

Windows 10/11 x64 原生小工具，Rust + Windows 原生控件。无 WebView、无 .NET 运行时、无后台服务和自动联网。每个版本会在 GitHub Actions 的干净 Windows 环境构建，并提供可直接运行的 Windows x64 压缩包和 SHA-256 校验文件。

## 一键启动

在项目目录双击 **启动 sys tools.cmd**。脚本会增量编译测试版，成功后打开窗口；失败时保留错误提示。不要移动该脚本或删除开发工具目录后单独运行。已经打开时会保留现有实例。

当前电脑的 Rust 工具链隔离放在 `.tools`，不修改全局 PATH。构建依赖本机已安装的 Visual Studio C++ Build Tools 和 Windows SDK。Cargo 依赖使用 lockfile 固定；因当前网络无法连接 crates.io，项目内配置了 rsproxy 镜像，可按网络条件调整 `.cargo/config.toml`。

## 已实现

- **软件管理**：读取当前用户和本机的 32/64 位卸载登记；即时搜索；按普通软件、更新组件、共享组件/驱动、系统组件分组，可折叠；窗口下方固定显示分类导航，点击即可展开对应分组，不必滚动寻找。调用原卸载程序。MSI 的有效产品代码 `/I` 调整为 `/X`；不猜测静默参数、不自动强杀、不把删除目录当作卸载。卸载完成后会重新检查安装目录、用户数据和共享数据，弹出二次清理确认。
- **磁盘清理**：选择固定磁盘后扫描并分类为临时文件、软件缓存、软件文件、软件数据、系统文件、用户文件/其他、迁移保护和目录链接；“快速扫描临时文件”只检查 Windows 和当前用户临时目录，避免为了清理临时文件遍历整块磁盘。结果落盘索引，按类别显示首批 500 项，清理前再次核对路径、时间、大小和文件身份。只有临时文件和明确可重建缓存可勾选，永久删除前需要确认。
- **迁移与恢复**：普通目录迁移到本地固定 NTFS 磁盘上的同名新目录；检查占用和空间，完整复制和 SHA-256 校验（包含 NTFS 数据流），保留权限与目录时间，在原位置建立 Junction。保留源副本，确认软件和数据可用后才释放。恢复始终复制目标盘最新数据，保留目标副本供确认。迁移记录支持右键打开原/目标位置、恢复、释放、修复和清理；只有已恢复或已回滚、且副本已释放并通过路径核验的记录可删除。
- **操作记录**：阶段记录原子写入，核对卷号与文件标识；取消和失败尝试恢复原路径；中断可从记录修复。遇到路径冲突、记录损坏或副本身份变化时停止，不覆盖新出现的内容。

## 推荐测试顺序

1. 先检查软件列表、搜索、保护项按钮和三个页面。
2. 使用一个可丢弃的小测试目录，内放文档、子目录和空目录，在另一位置选择目标父目录。迁移后通过原路径读写，再恢复；确认新增数据也被恢复。
3. 检查迁移期间取消、目标同名目录已存在、文件被占用等场景。遇到中断保留 `data` 目录及所有副本，从记录修复。
4. 确认上述操作正常后，再选择无重要数据的普通第三方软件测试。卸载是实际操作，请自行确认所选软件。

## 当前边界

- 软件列表覆盖登记为 Win32/MSI 的项目，不代表电脑上所有可执行程序。Store/UWP、孤立绿色软件、批量与强制卸载暂未实现；残留复查目前按识别结果整体确认，尚未做逐项复选框。
- 分类依据安装登记与少量保守规则，不是任意系统文件的完整鉴定。共享运行库、驱动、系统和更新组件默认不可卸载、不可迁移。
- **比特浏览器整套迁移尚未验证**。浏览器安装目录入口保守限制；不要直接对真实环境目录试搬。后续需单独核对程序、内核、环境、缓存、后台进程及升级行为。
- 程序启动时会自动请求管理员权限；迁移要求软件及后台进程已退出，操作完成前不要重新启动。切换到目标目录并建立链接后会再次核对链接、目录身份和文件清单，校验失败会报警并自动回滚、保留副本。占用检查与静态校验不能代替应用自身的一致性机制。
- 首版拒绝目录内的重解析点、硬链接、加密、离线和稀疏文件；磁盘扫描索引上限为 1 GiB、目录深度 256 层，迁移目录上限为 10 万项、128 层。临时文件预览上限为 1 万项。遇到权限不足会停止，不自动接管所有权。
- 原副本未释放前，原盘占用仍保留。恢复需要原盘有完整副本空间，恢复后目标盘副本也不会自动删除。
- 记录保存在可执行文件旁的 `data` 中。不要在迁移生效期间删除记录、改动目录链接或手动移动目标。

## 开发验证

```powershell
.\build.ps1 -Check
.\build.ps1 -Test
```

测试仅创建与操作独立测试目录，不卸载实际软件。当前未以真实比特浏览器环境作兼容性验证。

## 发布包

GitHub Release 中的 `systools-<版本>-windows-x64.zip` 包含 `systools.exe` 及许可证和第三方声明。解压后直接运行 `systools.exe` 即可；程序会自动请求管理员权限。下载后可使用同名 `.sha256` 文件校验压缩包完整性。
